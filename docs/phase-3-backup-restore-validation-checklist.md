# Phase 3 Backup Restore Validation Checklist

## Purpose

Phase 3 is a manual validation checklist for the backup and restore behavior added in Phase 2.

This phase does not change application code. It documents what must be checked before moving to deeper storage adapter wiring.

## Scope

Check only the Settings backup and restore flow.

Do not change or retest unrelated business logic unless a backup restore result affects it.

## Pre-check

Before testing, confirm:

- the app opens normally;
- login still works;
- Settings page opens;
- Backup button is visible;
- Restore button is visible;
- current browser data is not needed, or a safe backup has already been saved.

## Test 1: New schema backup export

Steps:

1. Open Settings.
2. Click Backup.
3. Save the generated JSON file.
4. Open the JSON file in a text editor.

Expected result:

The file should include:

- appName
- schemaVersion
- exportedAt
- data

The data section should include:

- products
- purchases
- sales
- dishes
- inventoryAudits
- activityLogs

Pass criteria:

- JSON opens without error;
- appName is HoReCa CostControl;
- schemaVersion is 1;
- data sections are arrays.

## Test 2: New schema backup restore

Steps:

1. Use a backup generated by Test 1.
2. Open Settings.
3. Click Restore.
4. Select the backup file.
5. Confirm restore.

Expected result:

- confirmation modal appears before restore;
- after confirmation, success message appears;
- app data is restored.

Pass criteria:

- restore does not crash;
- success message appears;
- main screens still open.

## Test 3: Legacy backup restore

Legacy backup format means the old direct object format without appName, schemaVersion, exportedAt, and data wrapper.

Steps:

1. Prepare an old valid backup file with direct sections.
2. Open Settings.
3. Click Restore.
4. Select the legacy backup file.
5. Confirm restore.

Expected result:

- confirmation modal appears;
- restore succeeds;
- old valid backup compatibility is preserved.

Pass criteria:

- old valid backup restores;
- no app crash;
- data appears in related screens.

## Test 4: Invalid JSON file

Steps:

1. Create a text file with broken JSON content.
2. Rename it to .json if needed.
3. Try to restore it from Settings.

Expected result:

- restore is blocked;
- error message appears;
- existing app data is not overwritten.

Pass criteria:

- no confirmation restore is applied;
- no data loss.

## Test 5: Wrong app backup file

Steps:

1. Create a JSON file with appName that is not HoReCa CostControl.
2. Include schemaVersion and data fields.
3. Try to restore it.

Expected result:

- restore is blocked;
- error message appears;
- existing data remains unchanged.

Pass criteria:

- no restore is applied;
- no data loss.

## Test 6: Future unsupported schema version

Steps:

1. Create a backup file with appName HoReCa CostControl.
2. Set schemaVersion to a number higher than the current supported version.
3. Try to restore it.

Expected result:

- restore is blocked;
- existing data remains unchanged.

Pass criteria:

- no unsupported future backup is applied.

## Test 7: Wrong section shape

Steps:

1. Create a backup where one restorable section is not an array.
2. Example: products is an object instead of an array.
3. Try to restore it.

Expected result:

- restore is blocked;
- existing data remains unchanged.

Pass criteria:

- validation blocks the file;
- no data overwrite occurs.

## Test 8: Empty backup object

Steps:

1. Create an empty JSON object.
2. Try to restore it.

Expected result:

- restore is blocked;
- existing data remains unchanged.

Pass criteria:

- no restore is applied.

## Final acceptance checklist

Phase 3 can be accepted when:

- new backup export works;
- new backup restore works;
- old valid backup restore works;
- invalid JSON is blocked;
- wrong app backup is blocked;
- future schema version is blocked;
- wrong section shapes are blocked;
- empty backup is blocked;
- app still builds successfully;
- main business screens still open after restore.

## Merge rule

Do not continue to storage adapter wiring until this checklist is either manually completed or explicitly accepted as a documented test plan.
